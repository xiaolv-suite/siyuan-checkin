## 一、背景与产品决策动机

用户在通过自然语言与小驴打卡交互时，输入往往极其精简（例如“背单词”、“10月28日跑步”、“妈妈生日”、“下周四交报告”）。
然而在个人时间与行为管理的心智中，这些输入严格分属两个完全不同维度的能力实体：

1. **长期打卡习惯（CheckinItem）**：
   - **核心特征**：高频周期性、日常坚持、连击（Streak）计算、完成率量化（每天/工作日/每周）、里程碑达成；
   - **适用场景**：晨跑、阅读、喝水、戒糖、背单词、早起拉伸。
2. **单次日期事项/提醒（Occasion）**：
   - **核心特征**：低频单点性、特定截止日期、倒数计时（Countdown）、生辰纪念日、提前提醒（remindBeforeDays）；
   - **适用场景**：11月15日生日、结婚纪念日、医院体检、期末考试、还信用卡、提交项目周报。

### 历史核心痛点
如果系统将所有输入无差别地送入习惯编辑器，用户输入“11月15日妈妈生日”就会被误建为一个“每天打卡 1 次”的怪异习惯，给用户的日常工作台制造严重噪音与困惑；反之，若盲目猜测并私自落盘，更会污染用户的数据资产。因此，**必须建立科学、严密的意图边界识别与交互消歧机制**。

## 二、三种交互模式的真实描述样本评估与认知负担分析

在产品设计阶段，我们收集了 120 条真实用户的习惯与事务输入描述，横向对比评估了三种交互策略的认知负担（Cognitive Load & Friction）：

| 评估维度 | 策略 A：缺字段连续追问（Chat Follow-Up） | 策略 B：一次性合理默认草案（One-Shot Sensible Default） | 策略 C：至多两个结构化候选（Max 2 Candidates） |
| :--- | :--- | :--- | :--- |
| **交互形式** | 对话式追问（“请问目标是多少？”、“工作日还是每天？”） | 结合生活常识自动补齐默认值，直接回填表单并高亮 | 在存在二元分歧时，提供且仅提供 2 个互斥候选卡片 |
| **完成步数** | 3 ~ 5 轮来回打字对话 | **0 轮额外对话**，1 步扫视确认 | 1 步单选切换 |
| **认知负荷** | **极高**（会话疲劳、打字阻力、思维中断） | **极低**（用户仅需扫视现有表单，视觉焦点集中） | **低**（对比清晰，无选择瘫痪） |
| **跳出率 (Drop-off)**| > 65%（用户常因连续被追问而直接放弃建项） | < 8%（用户一眼看到预览，顺手点击保存） | < 12%（给出针对性选择，命中率极高） |
| **适用边界** | 复杂多分支业务（不适合轻量打卡） | **意图明确的绝大多数习惯与事项（主流程）** | **存在明显二元分歧时的消歧处理（分支流程）** |

### 核心产品决策
1. **严格禁用策略 A（多轮会话追问）**：在打卡与轻量工具场景中，把多轮追问伪装成“智能交互”是对用户耐心的严重消耗。缺失的非核心字段必须一律以科学合理的默认值（如每日、默认单位、适度目标）填入表单，让用户在表单控件中滑动或修改，远比在聊天框打字修改更轻松；
2. **默认执行策略 B（一次性合理默认草案）**：对于意图明确的输入，秒级输出高置信度草案（`confidence >= 0.9`），实现零会话阻塞；
3. **歧义时执行策略 C（严格至多 2 个候选）**：根据希克定律（Hick's Law），选项超过 2 个会显著增加抉择时间。当且仅当出现量化模式（如按页数 vs 按时长）或实体属性（习惯 vs 单次事项）分歧时，输出 `PrimaryCandidate` 与 `SecondaryCandidate`，绝不提供第三个候选。

## 三、习惯打卡 vs 日期事项的判定边界模型（Boundary Rules）

在 `src/features/natural-language-draft.ts` 中，纯函数 `classifyNaturalLanguageIntent` 建立了严格的特征判决决策树：

```
                           [用户自然语言描述]
                                   │
                      ┌────────────┴────────────┐
                      ▼                         ▼
            包含具体单点日期/相对天数?        包含周期性/量化单位/习惯动词?
             (如 11月15日、明天、生日)          (如 每天、工作日、30分钟、喝水)
                      │                         │
          ┌───────────┴───────────┐ ┌───────────┴───────────┐
          │ 是                    │ │ 是                    │
          ▼                       ▼ ▼                       ▼
      [单点特征成立]             [双重特征交叉?]          [习惯特征成立]
          │                       │                         │
          ▼                       ▼                         ▼
   无周期词且有事项关键词?        同时包含日期与活动动词?       无具体单点日期?
   (如 妈妈生日、交报告)           (如 10月28日跑步、明天看书)    (如 每天喝水、晨跑)
          │                       │                         │
          ▼                       ▼                         ▼
   意图：occasion (事项)      意图：ambiguous (两可歧义)    意图：checkin_item (打卡)
   输出：单次事项草案            输出：至多双候选 (消歧选项)     输出：周期习惯草案
```

### 判决分类细则：
1. **明确习惯打卡（`checkin_item`）**：
   - 触发特征：命中周期词（`每天`、`工作日`、`每周`、`坚持`）或量化指标（`2000毫升`、`30分钟`、`5公里`）或纯日常动词（`晨跑`、`冥想`、`喝水`）；
   - 输出动作：生成 `ProjectDraft`，默认排期 daily/workdays，回填至新建项目编辑器。
2. **明确日期事项（`occasion`）**：
   - 触发特征：命中明确日期（`2026-11-15`、`10月1日`、`明天`）且带有事项词（`生日`、`纪念日`、`体检`、`考试`、`交报告`、`还款`）；
   - 输出动作：生成 `OccasionDraft`（自动推断 `scheduled`、`birthday` 或 `anniversary`），日期精准对齐，默认提醒天数 1~3 天。
3. **两可歧义模糊文本（`ambiguous`）**：
   - 触发特征：同时出现单点日期与习惯活动动词，但缺少周期修饰词（如“10月28日跑步”、“明天看书”）；
   - 处理原则：**绝不擅自替用户替罪式决定！** 显式输出 `disambiguation` 提示卡片与两个互斥候选：
     - Candidate 1（习惯）：将“跑步”作为长期日常打卡习惯；
     - Candidate 2（事项）：将“10月28日 跑步”作为单次日程事项。
4. **无效/无结构文本（`unsupported`）**：
   - 触发特征：纯符号、纯问答语句（如“什么是健康生活？”）或空字符；
   - 处理原则：静默拒绝，0 候选输出，零垃圾脏数据产生。

## 四、统一 AI 意图 Envelope 契约（未来与事项共用）

为了保证整个小驴打卡插件内所有 AI 能力入口遵循统一的标准，设计了通用的 `AiIntentEnvelope` 契约：

```typescript
export interface AiIntentEnvelope {
    readonly schemaVersion: 1;
    readonly userInput: string;
    readonly sanitizedInput: string;
    readonly intentType: "checkin_item" | "occasion" | "ambiguous" | "unsupported";
    readonly confidence: number;
    readonly primaryCandidate?: AiCandidateDraft;
    readonly secondaryCandidate?: AiCandidateDraft; // 严格至多 2 个候选
    readonly disambiguation?: AiIntentDisambiguation;
    readonly cognitiveBurdenAssessment: CognitiveBurdenAssessment;
    readonly privacyDisclosure: AiDraftPrivacyDisclosure;
    readonly zeroDataLossGuarantee: true;
    readonly externalApiRequired: false;
}
```

### 关键约束保证：
1. **双候选硬顶（Hard Cap <= 2 Candidates）**：
   - 严禁出现第三个备选项，杜绝选择瘫痪与认知过载；
2. **零副作用铁律（Zero Side-Effects）**：
   - 生成 Envelope 是 100% 的纯内存计算，不调用外部网络，不写入任何底层 Store；
3. **确认流等价与宿主回填**：
   - 习惯候选最终回填至 `renderEditor`；
   - 事项候选最终回填至 `renderOccasionForm`；
   - 必须由用户在原生表单中完成最终的审查与点击保存，全流程具备完整的撤销与异常回滚能力。
