# 显式“未达成及原因”语义评估与跨页面语义矩阵研究报告（T-1634 收官）

## 1. 调研背景与问题陈述

在小驴打卡既有的数据模型与日常交互中，打卡事件 `CheckinEvent.kind` 仅包含两大类型：
- **`checkin`（打卡）**：用户完成了打卡目标（部分达标或全部完成）；
- **`skip`（请假/跳过）**：用户主动声明今日跳过（例如休息日、生病或出差）。

然而，基于对主流打卡应用（如 **TickTick 的 Unachieved**、**Habitify 的 Pause & Reflect**）的长期追踪以及行为科学研究（**"Never miss twice"** 与无罪化复盘心理学），用户在日常习惯养成中存在一个强烈的真实心理学痛点：

> **“今天我本该去健身或阅读，但我因为加班太累/拖延没能去成。我想诚实地记录下我今天没做成，并写下原因供周末复盘，但我既不想作弊点打卡，也不想点‘请假（Skip）’假装这天本来就可以不做，更不想干脆不理它让它留白，因为留白在复盘时分不清究竟是‘我忘了打开插件’还是‘我真没做到’。”**

为此，本研究围绕 **T-1634 显式“未达成及原因”语义评估**，深入探讨其真实使用场景、用户心理价值、事件身份定义、连击与分母口径、低压力文案原则以及跨页面语义矩阵。

## 2. 四态语义正交模型（Done vs Skip vs Unachieved vs Unrecorded）

为彻底消除概念模糊，系统化确立习惯在某一计划日的四态语义模型：

| 维度 / 状态 | ① 完成（Done） | ② 请假（Skip） | ③ 显式未达成（Unachieved） | ④ 遗漏未记（Unrecorded） |
| :--- | :--- | :--- | :--- | :--- |
| **用户心理动机** | 达标执行，获得胜任感与即时成就 | 计划内休息或不可抗力，合理保护连击 | 诚实面对错失，主动留下反思，获得心理闭环 | 忙碌、遗忘或放弃，无任何主动交互 |
| **完成度分子** | $+1$（或按进度累加） | $+0$（不贡献完成计数） | $+0$（不贡献完成计数） | $+0$（不贡献完成计数） |
| **可评估分母** | 计入分母 | 计入分母（作为计划机会） | 计入分母（作为计划机会） | 计入分母（闭合日自然结算） |
| **连击影响（Streaks）** | **连击 $+1$** | **连击保持（冻结不断连）** | **连击明确中断（重置为 0）** | **连击中断（重置为 0）** |
| **反思原因备注** | 支持记录完成心得与照片 | 支持记录请假事由（可选） | **支持记录阻碍与摩擦原因（可选）** | 无原因 |
| **今日催办提醒** | 立即关闭当日提醒 | 立即关闭当日提醒 | **立即关闭当日提醒（免打扰）** | 持续在预设时刻提醒 |

### 核心区分点：Skip vs Unachieved
- **Skip 是“免责豁免”**：连击不中断，代表“我今天按规则休息”；
- **Unachieved 是“诚实认错”**：连击中断，代表“我今天确实没做到，但我选择正视并反思”；
- 两者均关闭今日催办，但数据意义与心理意义完全正交。

## 3. 低压力文案与反思设计原则（Calm & Supportive Copy）

行为科学与积极心理学（Positive Psychology）明确指出：**过度惩罚性的文案（如“违规”、“破戒”、“失败”）会引发用户的防御性逃避与弃用插件心理**。因此，文案设计必须严格遵循“无罪化、支持性与成长心态”：

1. **禁用负面羞辱性词汇**：全仓严禁出现“失败”、“破戒”、“失信”、“惩罚”等字眼；
2. **采纳中性与成长心态文案**：
   - 动作入口：`今天没做成`、`标记未达成`；
   - 状态提示：`已记录未达成`、`留下反思（可选）`；
   - 鼓励引导：`完全没关系，反思是前进的开始`、`明天重新出发`；
3. **输入原因绝对可选（Strictly Optional）**：
   - 输入框作为抽屉展开，提供一键“直接确认”；
   - 绝不强制要求用户必须写小作文才能完成操作，严禁让反思变成二次认知负担。

## 4. 跨页面全景语义矩阵（Cross-Surface Matrix）

| 界面表面 | 呈现与交互契约 | 用户感知价值 |
| :--- | :--- | :--- |
| **Today 今日页** | 卡片长按或右滑菜单提供“今天没做成”；点击后呼出轻量反思输入抽屉；提交后卡片灰显移入底部“今日已结算区”，显示灰色空心微圆点，同时静音该项目今日后续全部系统与页内提醒。 | 消除未打卡项目的视觉催促焦虑，给今天画上明确句号。 |
| **Review 复盘页** | 在周复盘（Weekly Review）第 2 步“阻碍与摩擦（Friction Analysis）”中，系统自动将本周记录的所有未达成原因提取并列为可选卡片，用户可一键勾选填入复盘报告。 | 将零散的日记反思自动升华为周维度的系统性调整策略。 |
| **Insights 洞察页** | 在 84 日习惯热力图与日历格中，以空心浅灰格子（或半透下三角）渲染“显式未达成”，与完全留白的“遗漏未记”形成鲜明视觉区分。 | 回顾时一眼区分哪天是因事请假、哪天是主动放弃、哪天是彻底遗忘。 |
| **Calendar 日历页** | 日历格中以微弱点位标识未达成事件，点击日历格展示当日未达成原因备注。 | 提供完整的生命周期时间线溯源。 |
| **API v5 & 数据导出** | 导出至 CSV/JSON 时，保留 `kind: "unachieved"` 或 `source: "unachieved"`；向旧客户端或外部工具导出时平滑映射为 `value: 0, status: "unachieved"`，保持向下兼容。 | 保证生态与备份数据资产不丢失。 |

## 5. 产品决策与实施路径（Product Decision & Roadmapping）

基于上述场景研究与技术影响评估，形成如下最终产品决策：

### 5.1 核心决策结论
1. **需求真实性确认**：显式“未达成及反思”具有扎实的用户需求与行为科学价值，能够有效提升用户的长期留存与复盘深度；
2. **现阶段实施策略**：**维持当前为规范与纯语义模型，暂不变更主存储 Schema**。
   - **原因分析**：当前主 Store 版本为 `version: 2/3`，`CheckinEvent` 的 `kind` 只有 `checkin` 和 `skip`。全仓超过 370+ 测试套件对事件模型的二元枚举有深度断言。直接将 `kind` 扩展为三态枚举会带来广泛的类型迁移与外部兼容成本；
   - **推荐落地路径（轻量化方案）**：在未来版本落地时，可通过 `kind: "checkin", value: 0, source: "unachieved"` 的平滑方式承接，既无需升级底座 Schema，又能在上层完全实现“显式未达成”的全部产品交互与周复盘联动。
