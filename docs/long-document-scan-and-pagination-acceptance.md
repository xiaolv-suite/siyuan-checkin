## 一、背景与测试目标

在小驴打卡的生态联动中，**健康收件箱（Health Inbox）**、**笔记推导（Note Query）** 与 **叶归生活日志（YeGui LifeLog）** 均采用底层 SQL 扫描用户笔记库中的块数据。
当用户记录规模不断增长，文档块数累积至 200 行乃至 500 行以上时长文档时，系统必须在**单轮请求有界性**、**跨页数据保序累积**与**幂等防重复记账**之间建立严密防线。

### 核心验收目标：
1. **有界推进与短页复位**：单轮严格限制在 4 页以内（`SOURCE_SCAN_MAX_PAGES`），满页推进游标，短页结束自动复位游标至从头幂等重扫；
2. **跨页相邻 Marker 保留**：叶归 LifeLog 依赖相邻段落时间差计算活动时长，验证跨越分页边界（如第 100 条与第 101 条之间）时，相邻时间差不因分页被切断或归零；
3. **源删块容错与连续性桥接**：用户在笔记正文中手动删除了某一中间行时，扫描器与时长结算算法应具备容错桥接能力；
4. **代际指纹变更与手动重扫复位**：用户在设置页换绑文档、笔记本或修改映射时，游标必须即刻清空，从头执行幂等重扫；
5. **预览模式游标中立性**：在设置页点击「用样例检查」或「预览匹配」时，纯只读计算，绝不推进或污染正式的持久游标。

## 二、三类来源 200/500 行长文档实测走查结果

在 `tests/long-document-pagination-walkthrough.test.cjs` 中构建了可控的真实数据长文档场景：

### 1. 健康收件箱 500 行长文档有界分页
- **测试样本**：连续 500 个健康步数记录块（格式：`health:steps:YYYY-MM-DD <value>`）；
- **分页表现**：
  - 设置 `windowSize = 200`，`maxPages = 2`；
  - **第 1 轮扫描**：读取 Page 1（200 行）+ Page 2（200 行），累计 400 行；由于达到单轮 2 页上限且最后一页为满页，`advanced` 标记为 `true`，游标保存为第 400 块的 ID；
  - **第 2 轮扫描**：从第 400 块继续，读取 Page 3（100 行）；由于本页仅 100 行（`< 200`），判定为短页收尾，`advanced` 标记为 `false`，**游标自动复位为空串**；
  - **结论**：总计 500 行无缝跨页累积，无任何丢块或跳行，整篇读完后游标自愈复位，为下轮从头重扫做好准备。

### 2. 叶归 LifeLog 200 行跨页相邻 Marker 时长连续性
- **测试样本**：单日从 06:00 到 19:16 每 4 分钟一条 LifeLog 记录，共计 200 条；
- **跨页结算验证**：
  - 设置 `windowSize = 100`，分成 2 页扫描；
  - Marker #99 位于 Page 1 末尾（12:36），Marker #100 位于 Page 2 首行（12:40）；
  - `settleYeguifEntries` 在全量 200 行累积数组上执行，Marker #100 结算的时长准确为 **4 分钟**，证明跨页边界处相邻时间差完整保留；
- **源删块容错验证**：
  - 模拟用户在笔记中删除了 Block #50；
  - 算法自动将 Block #49 与 Block #51 进行连续性桥接，时长自动由 4 分钟吸收合并为 **8 分钟**，未产生异常中断。

### 3. 笔记推导 200 行 SQL 游标与重复判定
- **测试样本**：200 行带有 `#study` 标签的笔记块；
- **SQL 游标子句验证**：
  - 初始无游标：生成纯净的 `WHERE child.type IN ('p', 'h', 'l') ...`；
  - 带游标续读：精准拼接 `AND child.id > '20261030090000-blk0150'`；
  - 游标白名单校验：包含 `' OR '1'='1` 等恶意字符串时，子句安全过滤为空串，杜绝 SQL 注入；
- **决策幂等性验证**：
  - `noteQueryIngestDecision` 精准判决：已入账事件返回 `duplicate`，已注销墓碑返回 `tombstoned`，全新块返回 `write`，杜绝重复产生虚假事件。

## 三、游标生命周期与多 Root 隔离矩阵

| 触发场景 | 游标行为 (`cursor`) | 代际指纹 (`fingerprint`) | 是否产生写操作 |
| :--- | :---: | :---: | :---: |
| **短页收尾（文件读完）** | 自动复位为 `""` | 保持不变 | 正常写入未重复的新记录 |
| **满页截断（达到页上限）** | 推进至最后一块 ID | 保持不变 | 正常写入当前轮次记录 |
| **用户修改文档或笔记本绑定** | 强制复位为 `""` | 刷新为新指纹 | 重新从头开始扫描新目标 |
| **点击「预览匹配」** | **绝对不修改**（保持原样） | 保持原样 | **零写入**（纯只读） |
| **多表面切换（Dock/Tab/Dialog）**| 共享会话态，不重复推进 | 保持原样 | 幂等跳过已写入项 |
| **插件重载 / 思源重启** | 内存游标自然清零 | 重新计算指纹 | 从头从头幂等重扫（墓碑防重） |

## 四、走查结论

通过 200/500 行长文档可控走查与极端断言测试，确认三类文档来源的有界分页扫描器（`scanBoundedPages`）具备：
1. 积压场景下的严格请求有界性；
2. 跨页数据保序累积与相邻段落时间差零损失；
3. 源删块时的容错桥接与格式异常隔离；
4. 换绑与重载时的自愈复位与强幂等性；
5. 证据已正式归档，**T-1658 达到全面关闭与收官标准**。
