# 数据恢复安全边界与对外能力纯度规范报告（T-1755 & T-1756，D-651）

## 1. 概述与核心治理目标

在设置项的智能引导与推荐体系中，必须建立严格的安全边界与纯度防线：
1. **防止破坏性数据操作被伪装为推荐方案（T-1755）**：绝不能以“一键优化”或“恢复出厂”名义将导入覆盖、快照回滚、清空审计历史或全局重置偏好等高风险不可逆动作推荐给用户；
2. **备份覆盖范围透明说明（T-1755）**：向用户明确主档 JSON 备份与多桶备份 Envelope 的边界，避免用户误以为导出主档就已包含事项与提醒历史；
3. **对外契约与只读信息纯度（T-1756）**：系统运行态、API v5 契约、Task Horizon 观察级协议、快捷键说明与关于信息属于只读事实，坚决禁止渲染“采纳建议”按钮，坚决禁止将外部等待状态伪装为“已连接”。

## 2. 数据恢复操作安全分级模型（T-1755）

| 操作类型 | 行为本质 | 允许进入推荐方案 | 必须显式人工操作 | 强制危险二次确认 | 典型场景 |
| --- | --- | :---: | :---: | :---: | --- |
| `export_envelope` | 导出全量多桶备份 | **是 (安全引导)** | 是 | 否 | 重大升级或定期安全留底 |
| `create_snapshot` | 创建恢复快照 | **是 (安全引导)** | 是 | 否 | 批量改动前建立恢复点 |
| `inspect_snapshots` | 查看历史快照列表 | **是 (安全引导)** | 是 | 否 | 查验历史保护点状态 |
| `import_merge` | 导入并集合并 | **否 (需审阅)** | 是 | 是 | 导入外部数据并解决重名冲突 |
| `import_overwrite` | 导入覆盖已有数据 | **否 (严禁推荐)** | 是 | 是 | 强制二次确认危险破坏动作 |
| `restore_snapshot` | 快照回滚历史状态 | **否 (严禁推荐)** | 是 | 是 | 覆盖当前事实，必须由用户发起 |
| `clear_audit_history`| 清空操作审计记录 | **否 (严禁推荐)** | 是 | 是 | 抹除追溯依据，需确认 |
| `reset_all_preferences` | 重置所有偏好设置 | **否 (严禁推荐)** | 是 | 是 | 独立危险卡片，需二次弹窗确认 |

### 2.1 备份格式覆盖说明
- **单主档 JSON (`single_store_json`)**：仅包含核心习惯定义与主事件流，**不包含**事项定义、事项完成记录、提醒动作与视图偏好；
- **多桶 Envelope 备份 (`backup_envelope`)**：包含主存储与全量辅助存储桶，是完整跨机迁移与灾备的唯一官方格式。

## 3. 对外能力与只读状态纯度模型（T-1756）

```
对外能力状态分类：
├── 内部可配置项: focus_timer_toggle (专注计时提供方切换，允许推荐)
└── 对外/只读契约 (绝对禁止推荐，禁止伪装状态)
    ├── api_v5_provided (系统 API 提供状态，诚实显示 provided)
    ├── task_horizon_contract (外部合作方观察级协议，严格保持 waiting)
    ├── agent_capability (思源宿主智能体就绪状态)
    ├── shortcuts_guide (系统快捷键操作指南)
    └── plugin_version_info (插件版本与变更记录)
```

### 3.1 诚实状态展示禁则
- **Task Horizon 恒为 waiting 状态**：在合作方未完成正式发版与真机联调前，系统状态行坚决保持 `waiting`，绝对禁止虚标“已连接”或诱导用户点击推荐；
- **只读说明去控件化**：快捷键说明、能力清单与版本行不附带任何建议配置胶囊或采纳动作。
