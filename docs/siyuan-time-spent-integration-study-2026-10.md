# 源时记（siyuan-time-spent）数据面适配可行性研究报告（2026-10-29，T-1676 / D-632）

> **研究背景**：承接 T-1540 与 D-298 决策，对思源集市被动时间统计插件「源时记（siyuan-time-spent）」开展数据面适配可行性评估。深入复核其 petal/JSON 数据所有权、跨窗口归属、时间段边界、停用与删除语义，明确小驴打卡在“主动习惯打卡 vs 被动时间量化”之间的工程边界。

---

## 一、源时记数据面现状与架构审计

1. **定位与数据存储机制**：
   - 源时记是一款面向思源笔记的被动时间统计插件，通过监听编辑器焦点与按键活动，记录用户在各个文档与块上的停留阅读/编辑时长；
   - 数据落盘形态：持久化于思源数据目录中的私有存储区（`data/storage/petal/siyuan-time-spent/*.json`）；
   - 数据结构：按日期分片存储 `docId`、`startTime`、`endTime` 及 `duration`（毫秒/秒）。
2. **与现有已支持来源的对比**：
   - **叶归 LifeLog**：读取的是用户日记文档中用户自己编写的文本段落（如 `12:00 工作：写报告`），数据完全属于用户公开笔记正文；
   - **微信读书**：经官方出站 HTTP API 拉取已授权的阅读数据，带服务端防伪造凭据与源时刻；
   - **源时记**：数据存储完全属于第三方插件的私有目录，上游未发布任何面向外部插件调用的公开 API、TypeScript 声明或导出规范。

---

## 二、关键适配维度的可行性复核

### 1. 数据所有权与私有存储红线（Data Ownership Redline）
- **风险**：若小驴打卡直接通过内核读取 `data/storage/petal/siyuan-time-spent/` 下的私有文件，一旦源时记在后续版本重命名字段、变更目录层级或切换为 SQLite 存储，小驴打卡将发生不可预期的崩溃或读取到脏数据；
- **红线**：根据架构守门纪律（R-A1 与 D-255），**严禁跨插件私自读取第三方插件的私有存储文件**；任何数据接入必须基于上游提供的稳定公开契约或用户主动导出的文件。

### 2. 跨窗口归属与双重计入防线（Cross-Window & Anti-Double-Counting）
- **现象**：思源用户常在多窗口/分屏中同时打开文档。源时记在多窗口下的时长累加可能存在时间戳重叠；
- **要求**：若接入时间来源，必须由接入层在入账前完成区间归一化与跨午夜切分（借鉴 `sireader-adapter` 与 `siplayer-adapter` 的单日切分纪律）；同一分钟数必须由单一 Canonical Source 互斥写入，严禁双写。

### 3. 停用与删除语义（Tombstone & Teardown Boundary）
- **要求**：用户在源时记中重置统计或删除某条记录，打卡系统必须坚守“打卡事实层不可变（Immutable Facts）”原则，严禁因源时记数据清除而级联删除用户历史打卡；
- **治理**：在设置页中若停用源时记映射，系统必须在锁内销毁所有在途轮询与监听器，确保零内存与代际泄漏。

## 三、采用 / 延后 / 不做 裁决矩阵

| 维度 | 提案形态 | 评估依据 | 裁决结论 |
| :--- | :--- | :--- | :--- |
| **保留前缀标识** | 注册 `timespent` 为合法外部身份前缀 | 格式 `timespent:<docId>:<localDate>`，保证未来扩展可解释性 | **采用（Adopted）** |
| **标准格式文件导入** | 允许用户手动导入源时记导出的标准 JSON/CSV | 走现有 `import-preview` 管道，用户主动确认，零权限风险 | **采用（Adopted，进入排期池）** |
| **后台被动自动摄取** | 插件后台常驻轮询源时记私有存储区 | 缺乏稳定公开契约，破坏私有存储隔离红线 | **延后（Deferred）**：等待上游发布稳定公开 API 或 CustomEvent |
| **自建被动追踪器** | 小驴打卡自行在思源内监听全文档按键与停留计时 | 违背低压力、极简主动打卡定位，徒增内存与电量开销 | **坚决不做（Forbidden）** |

---

## 四、最终结论与后续触发条件

1. **研究结论收口**：
   - 现阶段**不启动针对源时记私有存储的自动监听与静默读取**；
   - 维持主动打卡与低压力记录的核心定位；
2. **未来重评触发条件**：
   - [ ] 源时记官方在集市发布稳定正式版本，并在 `README` 或文档中明确定义对外开放的公共只读 API（如 `window.__timeSpent.getDailySummary` 或标准 CustomEvent）；
   - [ ] 提供了明确的会话排他性说明（多窗口不重叠）；
   - [ ] 提供了标准的外部导出格式。
