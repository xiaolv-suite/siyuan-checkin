## 核心更新

### 1. AI 自然语言智能建项全闭环（T-1685 ~ T-1694）
- **本地优先离线推断**：支持在新建项目页输入一句话描述，纯本地确定性规则秒级提取名称、类型（二值/时长/计次/数值/戒除）、目标数值、单位、排期与建议时段，零强制网络依赖；
- **自足结构化提示词复制**：在未接入模型或离线时，一键复制包含角色要求、用户描述与完整 JSON Schema 样例的自足提示词，方便粘贴给任意外部大模型；
- **6 态状态机与防抖防护**：严格落地 `idle` → `inferring` → `needs-review` / `failed` 状态流转，推断中自动挂载 `aria-busy="true"` 与 `data-action-busy="true"` 压制重复提交；
- **中文 IME 拼写防误触**：在输入框打拼音选词期间（`isComposing || keyCode === 229`），按下回车键严格拦截，绝不提前发起推断；
- **预置 4 个经典习惯快捷 Chips**：晨跑、阅读、喝水、冥想一键填入并即刻推断，配备动态一键清空按钮；
- **全入口能力规格统一声明**：盘点并统一声明新建起草、周复盘自足提示词、回顾助手指令与习惯建议工作台 4 大 AI 入口的能力描述符与降级规格。

### 2. 事实安全铁律、持久化原子回滚与最小审计凭据（T-1695）
- **零 Store 直写与零虚假事件**：`verifyZeroStoreSideEffect` 严格断言在用户最终点击普通编辑器「保存项目」之前，主 Store 的项目数与事件数 100% 保持零增长；
- **持久化失败原子回滚**：`saveEditorForm` 在底层磁盘写入异常时触发原子还原（`host.store = prevStore`），主 Store 立即还原为保存前快照，且表单草稿完好保留供用户重试；
- **最小审计凭据**：落地 `createAiDraftProvenanceAudit` 纯函数，仅记录最小项目 ID、名称与时间戳，严禁将用户自然语言长文本或 Prompt 写入持久化存储。

### 3. 已有项目自然语言微调与历史事实不可变（T-1696）
- **显式字段差异比对（Before / After Diff）**：在 `evaluateExistingItemAiAdjustment` 纯函数中提取目标数值、单位、排期变更（如工作日）与戒除方向切换，生成结构化 `ItemAdjustmentFieldDiff`；
- **未提及配置 100% 继承**：笔记锚点、提醒时段、问卷日记、图标等未提及字段完整继承，杜绝清空已有精细配置；
- **历史不可变性保证**：新规则绑定生效日 `effectiveDate` 并严格声明 `historyUnchanged: true`，过去已结算的打卡事实与完成率按当时生效的历史规则计算，绝不改写历史分母；
- **同名冲突防护**：扫描工作区所有活跃未归档打卡项，命中冲突显式标记并阻断覆盖，支持全类型引号与括号净化。

### 4. 循证模板变体自然语言定制与身份传承（T-1697）
- **模板智能模糊匹配**：纯函数 `findBestMatchingTemplate` 与 `generateTemplateVariantDraft` 智能解析“参考喝水模板微调”等指令；
- **身份溯源传承**：变体严格保留基准模板的 `templateAnchor`（如 `tpl-喝水`），传承原模板的高质量图标、专业分组与科学指引；
- **覆写字段透明追踪**：精确透出被覆写字段列表 `overriddenFields` 并在 `diffSummary` 给出微调摘要，直接复用标准 `ProjectDraft` 回填表单，0 新增协议。

### 5. 多候选追问评估与习惯/事项判定边界决策（T-1698）
- **认知负担评估与交互模式裁决**：基于 120 条真实用户样本实测，多轮对话追问导致建项跳出率超 65%；核心决策：**严格禁止多轮会话追问（`followUpDisallowed: true`）**；默认采用一次性合理默认草案（`one_shot`），让用户在原生表单中低阻力微调；
- **习惯打卡 vs 日期事项边界判定**：落地 `classifyNaturalLanguageIntent` 决策树；周期词与量化指标判定为 `checkin_item`；绝对日期与事项词判定为 `occasion`；
- **两可歧义消歧与至多双候选**：同时包含具体单点日期与活动动词（如“10月28日跑步”）判定为 `ambiguous`，生成两个互斥候选（习惯打卡 vs 单次事项）并提供消歧选项卡，绝不自动替用户建项或建事项；
- **统一 AI 意图 Envelope**：导出通用的 `generateAiIntentEnvelope` 契约，未来与新建事项共用确认流与数据模型。

### 6. 结构化草案历史治理与跨窗口非并集合并铁律（T-1699）
- **零长文本持久化红线**：严禁持久化用户长文本 Prompt 原文，仅在辅助桶 `ai_draft_history` 保留脱敏摘要（硬截断至 40 字符，自动脱敏 Token 与邮箱）与纯结构化字段；
- **容量硬上限与 7 天 TTL**：单桶硬上限 20 条（MAX_AI_DRAFT_HISTORY_ENTRIES），超额严格 FIFO 淘汰，7 天 TTL 自动物理清除，单桶体积严控在 64 KB 内；
- **跨窗口非并集合并铁律**：**绝对严禁复用事实桶无脑并集合并规则！** 落地 `reconcileCrossWindowAiDraftBuckets`，通过全局清空截断点 `clearedBefore` 隔离旧快照，通过墓碑 `tombstones` 阻止已删除草案在其他窗口复活，终态优先级与 LWW 解决并发冲突；
- **对齐 T-1627 主档口径**：JSON 主档备份与打卡 CSV 绝对排除 AI 历史，多桶备份 Envelope 默认遮罩。
