# v18.43.0 变更记录 (2026-10-28)

## 核心台账核销

### T-1684 外部来源迟到响应配置代际守门与写前动态复核（D-607）
- **六大外部生态代际守门全覆盖**：为微信读书、叶归 LifeLog、健康收件箱、笔记推导、思播、思阅六大外部来源建立全面的请求与会话代际守门；
- **写前动态复核**：在 `enqueueMutation` 锁内写事实前，动态复核来源启用状态（`enabled`）、目标项目绑定（`itemId`, `finishItemId`, `notesItemId`, `metricBindings`）、笔记本/文档有效性以及配置指纹（`fingerprint`），并在叶归中动态复核分类映射解析，迟到响应可诊断丢弃，坚决不写旧目标；
- **重载与卸载阻断**：在偏好变更、偏好重载（`applyViewPreferences`）和插件卸载（`onunload`）时统一自增所有外部来源代际，立即使全部在飞请求失效；
- **专项守门测试**：落地 `tests/external-late-response.test.cjs` 守门测试并纳入 `test:v18` 门禁。

### T-1670 API v5 超时、取消、错误码与敏感字段边界强化与全面核销（D-611）
- **取消信号全覆盖**：在 `recordEventsBatch` 与 `getEventsInRange` 全面支持 `signal?: AbortSignal`，中止时分别抛出结构化取消异常；
- **宿主未就绪快速失败**：写接口统一快速拒绝，读接口安全返回受控空集合，杜绝挂起；
- **参数校验异常统一规范**：参数异常统一前缀为 `"checkin: "` 与 `TypeError`，`getStreaks` 增加 200 项输入消毒截断保护；
- **敏感字段脱敏与来源防伪造纪律**：外部公开写入严格限定为 `source: "api"`，严禁冒充内部适配器来源；公开诊断 `getDiagnostics()` 强化 `wrk-*` 凭据与绝对路径脱敏；所有返回对象深度防御性克隆与冻结；
- **契约测试同步**：`tests/api-v5.test.cjs` 补齐取消、未就绪、参数异常、来源防伪造与诊断脱敏全量断言。

### T-1799 事件墓碑生命周期治理与级联删除规范化收口
- **级联删除去重收口**：在 `deleteItemsCascade` 中统一调用 `normalizeEventTombstones` 规范化，消除脏墓碑未去重未排序隐患；
- **性能与安全边界**：固化 50k 事件与 25k 墓碑级规范化与检索性能；对齐《T-1799 墓碑生命周期设计》安全边界。

### T-1662 提醒排期计划预览、恢复今日提醒与 DST/跨午夜安静时段矩阵（D-608）
- **计划预览状态矩阵**：在 `features/reminder-delivery.ts` 落地 `unmuteReminderDeliveryToday` 与 `buildReminderPlanPreview`，全面覆盖 `delivered`、`quiet`、`muted`、`due`、`upcoming`、`disabled` 六大槽位状态；
- **恢复今日提醒自愈**：设置页直观呈现今日静音提示与计划预览，并提供“恢复今日提醒”（`unmuteDailyReminderTodayFor`）操作；
- **环境韧性与幂等性**：严格验证 22:00~07:00 跨午夜安静时段、夏令时/冬令时（DST）本地挂钟时间与修改槽位多窗口强幂等；
- **专项守门测试**：落地 `tests/reminder-schedule-preview.test.cjs` 守门测试并纳入 `test:v18` 门禁。

### T-1752 提醒方案推荐草案与实际触发预演（D-609）
- **四大典型提醒方案推荐**：在 `features/reminder-preferences.ts` 落地 `REMINDER_PRESET_SCHEMES`（minimal 低打扰、morning 晨间规划、review 早晚复盘、frequent 全天四段），设置页提供一键填入草案胶囊；
- **实际触发预演与真实影响解释**：落地纯函数 `simulateReminderTimeline`，区分“默认启用且无 slots＝启动后一条”和定时槽提醒两大模式，精准展示当天与次日未来触发本地时刻序列；
- **安静时段与事项仅一次真实影响**：对 22:00~07:00 跨午夜安静时段与事项提前提醒仅一次（`occasionRemindOnce`）选项做出直观影响解释；
- **用户确认纪律**：具体时刻和启用权严格由用户点击“保存时刻”确认生效，坚决不私自静默改写或隐式持久化；
- **专项守门测试**：落地 `tests/reminder-preset-simulation.test.cjs` 守门测试并纳入 `test:v18` 门禁。

### T-1659 外部来源统一调度、退避与省电策略矩阵（D-610）
- **六大外部来源统一调度矩阵**：在 `features/source-scheduler.ts` 落地纯模型，收拢微信读书、叶归 LifeLog、健康收件箱、笔记推导、思播、思阅六大外部来源生命周期；
- **失败指数退避与自动自愈**：各外部来源发生异常或读取/写入失败时自动进入指数退避（微信读书 base 30s / max 30min，叶归/健康 base 15s / max 5min），杜绝故障期密集循环轰炸；成功后自动清零自愈；
- **回前台防抖节流**：不可见期间跳过轮询省电省流，窗口回焦（`handleWindowFocus`）统一防抖节流（微信读书 60s，其余 30s），严格保障“回前台只补一次”；
- **可解释性状态查询**：暴露 `getSourceSchedulerSummary()` 只读状态矩阵；
- **专项守门测试**：落地 `tests/source-unified-scheduler.test.cjs` 守门测试并纳入 `test:v18` 门禁。

### T-1661 外部来源新鲜度、跨日切分与源时刻凭据（D-612）
- **四类来源事实凭据模型**：在 `features/source-provenance.ts` 落地纯模型，统一规范“来源原始发生时间、摄取到达时间、结算业务日与时间窗口”，严禁用摄取时刻冒充源事件时刻；
- **历史日汇总业务日锚定**：微信读书落地 `resolveSourceActionMoment`，当结算日早于摄取日时，事件发生时刻严格锚定在该业务日内（`23:59:59`），杜绝因几天后才拉取而将 `occurredAt` 误写为当前摄取时间；
- **段落时刻与跨午夜切段对账**：叶归 LifeLog 严格保留 Marker 段落源发生时刻；思阅与思播严格遵守跨午夜切段与源段时刻映射；
- **新鲜度评估矩阵**：落地 `evaluateSourceFreshness` 四态评估矩阵（`live` / `delayed` / `stale` / `idle`）；
- **专项守门测试**：落地 `tests/source-freshness-provenance.test.cjs` 守门测试并纳入 `test:v18` 门禁。
