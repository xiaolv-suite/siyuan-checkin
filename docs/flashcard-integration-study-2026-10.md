## 一、宿主 3.9.0 闪卡重构现状与证据（截至 2026-10-29）

1. **版本与发布事实**：
   - 当前思源官方稳定版仍为 **v3.8.5**（小驴打卡 `minAppVersion: "3.8.4"`）；
   - 思源官方 3.9.0 里程碑（包含 issue #10471 闪卡重构、#19353 动态复习队列、#19365 插件自定义复习顺序、#19344 卡片源历史等 18 个 issue）虽然在主干与分支上开发就绪，但**尚未向全网集市发布正式稳定版本**；
   - 官方 `docs/API.md` 尚未纳入全新的 `/api/flashcard/*` 专节，`node_modules/siyuan/siyuan.d.ts` 尚未收录 `options.card.review.{cardIDs,reviewSetIDs,reviewMode}` 插件类型定义。
2. **底层数据模型变化**：
   - 旧版基于 Riff 算法的 18 条 `/api/riff/*` 接口已在分支中被物理移除；
   - 重构为全新的 38 条 `/api/flashcard/*` 会话式端点（`startSession` / `reviewCard` / `finishSession` 等）；
   - 卡片与源块完成解耦（`flashcard_v2.go` 引入 `CardSource` / `CardSourceRef`）。
3. **副作用风险查清**：
   - 宿主内核中 `getDeckDueCards` 逻辑在已复习卡片参数为空时，会静默清空当前复习栈与跳过缓存；
   - 因此，**绝不能在插件后台轮询该接口**，否则会直接破坏用户原生的复习流程与缓存进度。

## 二、四种联动方式重评与裁决结论

| 联动形态 | 交互与技术机制 | 依赖接口等级 | 风险与副作用 | 裁决结论 |
| :--- | :--- | :--- | :--- | :--- |
| **① 人工打开原生复习/源文档** | 打卡项绑定文档后，提供“去复习”入口，调用公开 `openTab` 打开源文档，或引导通过顶栏原生按钮复习 | 公开稳定的 `openTab` API | 零副作用，不碰内核调度 | **采用（Adopted）**：最安全且体验闭环，已在现有 UI 中就绪 |
| **② 只读到期概览（Due Overview）** | 在打卡卡片或洞察页展示指定文档/牌组当前待复习卡片数（如“今日待复习 12 张”） | 需专用只读查询接口（目前无） | 调用现有端点会清空宿主复习栈缓存（高危破坏） | **延后（Deferred）**：等待宿主正式版提供带无副作用保证的只读概览端点 |
| **③ 复习完成后确认记账** | 用户完成学习后，通过快捷打卡或日记生成记录一次学习事实 | 现有打卡 API / 手动确认 | 零伪造风险，用户主动留痕 | **采用（Adopted）**：符合“打卡即笔记”原则 |
| **④ 自动监听私有事件与篡改调度** | 监听宿主内部复习按键/事件自动入账，或由插件计算 next due 回写宿主 | 私有 DOM / 未公开内部事件 | 调度所有权冲突，两套 FSRS 算法踩踏导致复习计划混乱 | **坚决不做（Forbidden）**：调度所有权 100% 归宿主内核 |

## 三、调度所有权与单向不可变红线（Core Invariants）

1. **宿主独占调度所有权不变量（Host-Exclusive Scheduling Invariant）**：
   - 闪卡的记忆状态、遗忘曲线参数、下一次复习日期（`due`）与牌组分类，**由思源宿主内核全权拥有**；
   - 小驴打卡绝不建立平行的卡片调度器，绝不试图向宿主写入或改写卡片 due，杜绝“两套算法同时调整同一学习对象”导致的知识库数据损坏。
2. **学习事实与打卡事实解耦**：
   - “复习了一组卡片”是学习行为；
   - “今日背单词打卡完成”是习惯承诺；
   - 插件只记录习惯承诺的达成事实（追加式 Event），不把卡片的每次评分（Again/Hard/Good/Easy）偷换为打卡数值。
3. **零私有监听与零轮询**：
   - 严禁通过 DOM MutationObserver 监听思源复习窗口的按钮点击；
   - 严禁定时轮询内核内部数据库统计表。

## 四、未来触发检查清单（When to Re-evaluate）

待以下条件在未来正式达成后，方可启动具体的联动功能扩展：

1. [ ] **思源正式发版**：官方集市正式推送思源 v3.9.0 或更高版本；
2. [ ] **公开契约就绪**：`/api/flashcard/*` 完整写入官方 `docs/API.md` 并承诺向下兼容；
3. [ ] **插件入口类型就绪**：`openTab.cardIDs` 明确在 `siyuan.d.ts` 中暴露为公开接口；
4. [ ] **无副作用查询就绪**：宿主明确提供无状态重置风险的只读卡片统计接口。
